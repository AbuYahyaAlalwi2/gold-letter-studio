# Migration 001 → 002

- **Migration ID:** `001-to-002`
- **Source schema:** `1`
- **Target schema:** `2`
- **Status:** implemented and covered by automated tests

## Change

Schema v2 adds the required field `metadata.lastSavedAt`, a canonical UTC ISO-8601 timestamp. The field records the last successful save timestamp written by the document-store API. It is distinct from `updatedAt`, which represents the document's content-update timestamp.

## Mapping

Schema v1 has no save timestamp. During migration:

```text
metadata.lastSavedAt = metadata.updatedAt
```

This is a documented fallback, not a claim that the old file was actually saved at that exact time. It uses the closest timestamp available in v1 without inventing a new historical time.

## Safety rules

1. Validate the complete v1 structure before transforming it.
2. Reject malformed v1 documents without producing a migrated project.
3. Do not mutate the input object.
4. Validate the result against the full v2 contract.
5. Loading a v1 file does not rewrite it. Persistence of v2 happens only after an explicit successful `saveProjectFile` call.
6. Unknown or future schema versions are rejected. No reverse migration is implemented.

## Regression coverage

`test/migrations.test.js` uses the fixed fixture `test/fixtures/project-v1.json` to assert the mapping, migration ID, non-mutation, invalid-input rejection, and future-version rejection. `test/document-store.test.js` additionally confirms that loading a v1 file leaves the source bytes unchanged.
